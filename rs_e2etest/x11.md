# E2E: Linux hotkeys through an X11 grab (rs_ui/hotkey_x11.py)

Harness: `rs_e2etest/x11_e2e.py`, run on Linux with an X server (CI: Xvfb +
xdotool, `.github/workflows/x11-e2e.yml`). Drives the real `rs_ui.hotkey`
start / restart / stop with the X11 backend, a Tk root pumping in the same
process, key presses sent by xdotool through XTEST.
Output: `rs_e2etest/out/<timestamp>-x11/report.txt` (CI: uploaded artifact).

## Ways it can fail end to end

1. libX11 not found / no DISPLAY: start raises instead of logging and
   falling back to chat.
2. A default combo (Ctrl+Alt+Z/B/M/D) pressed: callback not fired, fired twice,
   or fired for the wrong key id.
3. NumLock or CapsLock on: the grab misses the press (lock masks not grabbed).
4. A combo not ours (Ctrl+Alt+Q) fires a callback.
5. Another X client holds Ctrl+Alt+B: the BadAccess error kills the process
   (default Xlib error handler) or takes the other three keys down with it;
   must be a warning for B only.
6. Our error handler replaces Tk's for good: a later X error on Tk's display
   is swallowed or crashes.
7. Tk pumping in the same process while the grab thread reads its own
   display: hang or Xlib threading crash.
8. restart() with a changed combo: old combo still grabbed, new one dead.
9. stop(): thread still alive, grabs not released (another client cannot
   take the combo afterwards).
10. Held key: autorepeat fires the callback over and over.
11. hotkey.available() / label() / chat(): with the grab live, label names the
    combo; chat commands still work on Linux as fallback.

## What the harness replaces, and what that hides

| Replaced | By | Hidden |
|---|---|---|
| KWin/Mutter + XWayland | Xvfb, a plain X server | grabs only firing while an XWayland window (Elite under Proton) has focus; a native Wayland window in front gets the key instead |
| Elite focused | nothing focused on Xvfb | Proton/Wine eating or double-delivering the chord |
| Flatpak sandbox | none | X socket reachable in the Flatpak (`--socket=x11` in the manifest, not run here) |
| a physical keyboard | xdotool (XTEST) | keyboard layout effects on keysym -> keycode |
| EDMC | Tk root + callbacks recorded | EDMC mainloop timing |

Acceptance for the hidden rows: #12 reporter on Bazzite (KDE Wayland, Flatpak EDMC).
